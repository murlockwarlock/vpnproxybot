# VHQ Partner API

Локальная копия рабочей сводки по `VHQ Partner API`, обновлённая `2026-04-15`.

Источник:
- публичный `https://vhq-connect.xyz/api-docs`
- рабочий контракт дополнительно сверялся по реальным ответам, которые использовались при внедрении
- важно: `api-docs` у VHQ — SPA; при повторной проверке нельзя полагаться только на HTML-обёртку страницы

## Аутентификация

- Заголовок: `X-API-Key: <key>`
- Без ключа API отвечает `401`
- Невалидный или выключенный ключ даёт `403`

## Методы

### Баланс

```http
GET ?action=balance
X-API-Key: <key>
```

Актуальный ответ, подтверждённый живым запросом `GET action=balance` `2026-04-15`:

```json
{
  "balance": 1000,
  "currency": "RUB",
  "pricing": {
    "lite": [
      { "days": 1, "price": 1 },
      { "days": 7, "price": 59 },
      { "days": 30, "price": 149 },
      { "days": 90, "price": 359 },
      { "days": 365, "price": 1199 }
    ],
    "basic": [
      { "days": 30, "price": 249 },
      { "days": 180, "price": 1379 },
      { "days": 365, "price": 2219 }
    ]
  }
}
```

### Покупка

```http
POST ?action=buy
X-API-Key: <key>
Content-Type: application/json
```

Тело:

```json
{
  "tier": "lite",
  "days": 7
}
```

Допустимые значения:
- `tier`: `lite` или `basic`
- `lite`: `1 / 7 / 30 / 90 / 365`
- `basic`: `30 / 180 / 365`

Типовой успешный ответ:

```json
{
  "order_id": "uuid",
  "config_url": "https://...",
  "tier": "lite",
  "days": 7,
  "charged": 59,
  "balance_remaining": 14941,
  "created_at": "2026-04-13T12:00:00Z"
}
```

Примечание на `2026-04-15`:
- живой ответ на `buy` для `lite / 1 day` пришёл без `config_url`
- вместо него VHQ вернул `branded_url`
- в интеграции нужно принимать оба поля: `config_url` и `branded_url`

### История заказов

Типовой ответ:


## Ошибки из опубликованной документации

- `401` — отсутствует `X-API-Key`
- `403` — неверный или неактивный API key
- `400` — не передан `tier` или `days`
- `400` — неверный `tier`
- `400` — неверный `days` для выбранного тарифа
- `402` — недостаточно баланса партнёра
- `502` — ошибка поставщика
- `500` — внутренняя ошибка

## Что используется в проекте

- Клиент: `bot/services/vhq_partner_api.py`
- Маршрутизация тарифов: `bot/services/vhq_routing.py`
- Для текущей витрины `darimiru` используются:
  - `Базовый (1 день)` -> `lite / 1 / 1`
  - `Базовый (7 дней)` -> `lite / 7 / 59`
  - `Базовый (1 месяц)` -> `lite / 30 / 149` на стороне поставщика, продаётся у нас с наценкой
  - `Премиум (1 месяц)` -> `basic / 30 / 249` на стороне поставщика, продаётся у нас с наценкой
- Старый `Лайт (1 месяц)` за `95₽` остаётся на `Marzban`
- Для VHQ доступов не показывается экран управления устройствами, потому что выдаётся готовый внешний `config_url`

## Операционные заметки

- Ошибки VHQ маппятся в человекочитаемый текст для клиента и в подробный алерт для админов.
- На проде должны быть заданы оба env:
  - `VHQ_PARTNER_API_URL`
  - `VHQ_PARTNER_API_KEY`
- Изменение прайсинга у поставщика надо сверять именно через `action=balance`, потому что там лежит актуальная матрица цен.
- У поставщика документация и живой `balance` могут расходиться. На `2026-04-15` живой API уже отдаёт `lite 1 day = 1₽`, хотя раньше в сводке было `2₽`.
- Для текущего `darimiru` маршрутизация больше не должна опираться только на `price_rub`, потому что в витрине есть наценка над закупочной ценой VHQ.
